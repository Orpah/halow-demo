# Orpah Demo 路线图 / 待办清单

> 按「Orpah 协议目标 + 物联网演示系统」两条线梳理的缺口清单。
> 记录于 2026-09-11。逐步实现，优先级 P0 > P1 > P2。
> 2026-09-11 补充：走失案件闭环、一个走失者多客户端、隐私/时钟、无认证防 spoof 优先级上调。
> 完整上下文见 `/memories/orpah-demo-roadmap.md`。

## 〇、范围原则（最高约束，2026-09-11 用户定）

> **ORPAH 是技术搜寻手段；demo 项目边界应取最小。**

- **只做「用无线技术找到人」这一段**：登记走失态 → 下发走失表 → 路由器发现上报 →
  服务器回执落库 → RSSI 定位 → 审计与告警。
  **ORPAH 不是公安办案系统**，不承载警务流程。
- **默认不做**（除非用户明确要求，且能论证它服务于「搜寻」而非「办案」）：
  组织/机构建模、角色与权限体系、警员身份、案件分配/派单/办案流程、多租户隔离。
- **判据**（每条新需求先过这一关）：
  **「让找人更快更准」→ 做；「让管理/流程更完整」→ 默认不做，先记本清单。**
- **「谁」的分层**：需要「谁」时止步于**审计标签**（自由文本 `actor`，见 §三）；
  需要「谁负责」（经办/分配）时先确认**是否存在真实运营方** —— demo 目前**无登录者**，
  自填标识不等于身份。
- **已应用**（2026-09-11）：「案件经办/分配」（见 §三）与「告警处置态/时效策略」（见 §三）
  均按此原则**只记录、不实现**。

## 一、设备与身份侧（最像「产品」的缺口）

- [x] **设备清册/注册**：客户端台账——SN、所属组织、CC、**绑定走失者/对象（一对多：一个走失者可挂多个客户端，如项链/鞋/眼镜）**、状态（启用/停用/丢失/报废）、首次入网时间、最近见时间。（`registry.py` + `registry.html`，2026-09-11 完成）
- [ ] **密钥/证书生命周期**：密钥生成→分发→轮换→吊销→退役闭环；ES256 公钥、HMAC 密钥与 SN 绑定；作废机制（CRL/OCSP 思路）。
- [ ] **多算法策略与降级**：按设备安全等级自动选 alg；私钥不可用/能量不足自动降级并告警。
- [ ] **无源/低功耗客户端建模（协议约束，非仅画像）**：无源唤醒周期、能量采集状态、上报间隔——能量决定上报频率与 alg 降级；demo 加「能量轴」。

## 二、定位侧（track 已模拟，离真用还差）

- [~] **真数据接入而非纯模拟（拆两阶段）**：阶段一——**单台无人机多点悬停**真实 report 聚合；阶段二——**多路由器并发**（补 `router_id`/`router_pos`，改 router/server 架构）。前后端统一数据模型/API，避免模拟与真实两套逻辑。
  - 已完成（2026-09-11）：前后端统一数据模型/API（`/api/ts/query`，契约见 `API.md`）；`track.html` 新增「真实上报（IoTDB 时序）」模式，直读 IoTDB 真实 RSSI 时序 + A/n 距离换算，模拟模式保留。
  - **阶段一已完成（2026-09-11）**：补上了「这个 RSSI 是在哪个**已知坐标**测到的」这一维 ——
    `stations.py` + `/api/stations`（契约见 `API.md` §7）+ `track.html` 真实模式的「定位站位」面板。
    观测两条路、写同一张表：**时间窗**（「打点」实时生成，或悬停计划 JSON 预置 `t0/t1`；
    窗内所有 report 取 RSSI 中位数）与**手动绑定**（把最新一条 report 的 RSSI 指派给某站位）。
    ≥2 个站位有观测即调用**模拟模式同一个** `trilaterate()` → 画站位 / 距离环 / 估计点。
    站位表存 SQLite（`stations` 表），重启不丢；示例悬停计划见 `stations.example.json`。
  - **阶段二未做（唯一剩余项）**：真实 `router_id` 仍是空串（`ui_server.py` 收到 report 时没传），
    多路由器并发需 router 侧各自带编号 + 坐标。当前用「悬停点」代替多站点，达到同一定位效果。
- [~] **定位质量量化**：GDOP/PDOP、加权最小二乘（权重随距离增大而减小，σ∝距离）、误差椭圆/置信半径、滑动平均 + 卡尔曼滤波。
  - 已做（2026-09-11）：**残差 RMS**（每个站位「测量 − 估计」逐条列出 + 总体 RMS 分级）、
    **GDOP**（估计点到各站位单位向量，越小越好）、**站位布局条件数**（λmax/λmin，∞ = 完全共线）
    用于「解不出来」时区分是站位几何不行还是距离环不相交。
    为何必做：恒定 RSSI 这类退化输入会让 LS 解落在「外接圆心」，看着像个正常坐标、实际无意义。
    实测：给一组由真值点反算的 RSSI → 精确解回 `(0.0, 0.0)`、RMS 0.0、GDOP 1.22。
  - 未做：加权最小二乘（σ∝距离）、误差椭圆/置信半径、滑动平均 + 卡尔曼滤波。
- [~] **单/双/三点策略自动化**：自动判定可用测点数 + 几何共线检测，不满足自动提示补站位。
  - 已做（2026-09-11）：可用测点数自动统计（真实模式「参与定位：n/t 个站位有观测」），
    不足 2 个时直接提示、不出估计点。
  - 未做：置信半径（站形条件数已能提示共线，见上）。
- [ ] **离线地图与野外包**：PMTiles/区域离线包切换、经纬度基点导入、轨迹导出 GPX/GeoJSON。
  - **授权约束（2026-09-11 核实，必须遵守）**：`tile.openstreetmap.org` 的 Tile Usage Policy **明令禁止离线**
    （"Offline use is not permitted on tile.openstreetmap.org"），也禁止预取/批量下载/建瓦片包；
    且无 SLA、可无预警封禁，policy 原文提醒「商业服务可能随时失去访问」。
    故本项**不得**基于 OSM 官方瓦片，必须自建瓦片（switch2osm，PMTiles 自建即合规）
    或改用明确允许离线的供应商。

## 三、案件闭环 + 安全事件与运维

- [x] **走失案件闭环（以人为单位，非单 SN）**：某人走失 → 标记（其名下所有设备进入走失态）→ 路由器发现任一台即视为发现该人 → 找回/撤销 → 结案。case 状态机 + 页面（`cases.py` + `case.html`，2026-09-11 完成）。多设备定位聚合并入「真实 report 聚合」。
- [x] **审计日志**（2026-09-11 完成）：走失标记、撤销、发现、验签（含被拒）、发布等业务事件持久化到 IoTDB `root.orpah.events`，`/api/ts/events` 可回读、`index.html` 有「事件历史」区，**重启后仍在**。
  - **谁**：事件带 `actor` 字段——人为操作（立案/结案）由页面随 POST 带上（共享组件 `ui_i18n.js` 的 `bootActorBox()`，值存 localStorage），自动事件记 `system`；事件历史只给人为操作显示操作者标签。
  - **保留期限**：`ORPAH_EVENT_RETENTION_DAYS`（默认 30 天，0=不清理），启动连上库后按期限清理一次；`/api/ts/events` 回 `retention_days`/`purged_upto`，页面显示「保留 30 天」。
  - **可筛选**：验签被拒的单写 `id_reject`（原来混在 `id_report` 的 detail 里，无法按类型筛）。
  - **未覆盖**（后续）：`/api/registry` 增删改、`/api/stations` 增删改/打点/绑定 这些写操作不产生审计事件；也无「谁」的鉴权/角色（仅自填标识）。
- [x] **告警与通知**（2026-09-11 完成，仅「页面红点」部分）：`alerts.py` 无状态规则引擎（长未上报 / 走失超时 / 签名失败率）→ `GET /api/alerts`，`index.html` 页头徽标 + 告警卡片，3s 轮询；条件消失则告警自动消失。
  - **阈值可配**：默认 30s / 180s / 5 条 / 0.5 是**演示压缩时间**（客户端 2s 一包），
    全部可用环境变量覆盖（与保留期限同机制，见 `API.md` §8）：
    `ORPAH_ALERT_NO_REPORT_SEC` / `ORPAH_ALERT_CASE_OVERTIME_SEC` /
    `ORPAH_ALERT_SIG_WINDOW` / `ORPAH_ALERT_SIG_FAIL_RATIO`。
    演示时若嫌「立案 3 分钟就报警」，设 `ORPAH_ALERT_CASE_OVERTIME_SEC=600` 即可（不用改代码）。
  - 未做：Webhook/邮件通知、SSE 弹窗、RSSI 突变/校验位连续失败规则、页面展示当前阈值。
  - ⚠ **已知设计缺陷（2026-09-11 用户提出，本次只记录、不实现）**：`case_overtime` 是**恒定 crit**——
    只要案件还是 `open` 就永远红着（`since` = 立案时间，级别不随时长变化），于是：
    1. **红点恒亮 → 被淹没**：红点变成常态背景，不再表示"有变化需要看"，
       连刚做的「新告警闪一下」也失去意义（底色永远是红的，看不出新旧的差别）；
    2. **级别无增量**：`持续 5 分钟` 与 `持续 10 小时` 同为 `crit`，
       分不出"刚超时、还没人管"和"已经在找人"。
    注意：业务上「10 小时没找到人」本就该一直显眼，所以问题不在"时长太长"，
    而在**缺少处置态**（下面 A 的依据）。
    候选方向（择一或叠加）：
    - **A. 加处置态（推荐）**：案件加「已接手/处置中」+ 接手人（记审计，复用 `actor`）。
      规则改为「超时 **且** 无人接手」才算告警；点「已接手」→ 红点消失、案件转入处置中跟踪
      （时长继续累计、案件页可见）。代价：`cases` 加状态字段 + `case.html` 按钮 + 过滤。
    - **B. 加时长上限**：超上限（如 `ORPAH_ALERT_CASE_MAX_SEC`，默认 24h）自动退出告警，
      理由是长期未结属"案件积压"，应在案件台账看。改动最小，但"长期没人管"在红点上不可见。
    - **C. 分级升级**：按持续时长换级别/文案。信息更细，但红点仍恒亮，"淹没"未解决。
    - 也可 A + B：A 为主，B 兜底（认领后仍超 24h 再提醒）。
- [ ] **案件经办 / 分配（"谁在办"）**（2026-09-11 用户提出，本次只记录、不实现）
  - **现状盘**：**立案已有**（`case_mark`，「标记走失 / 立案」）；**分配/经办没有** ——
    案件无归属人、无"派给谁"动作。仅有三个**自由文本**信息位
    （`police` 警方联系人 / `police_case_no` 案件编号 / `police_station` 受理单位），
    **信息位留了、实体没建**。
  - **`actor` 现状**（别误读）：只是审计里的**自由文本标签**（`case.html` 的「操作者」输入框
    → localStorage → `root.orpah.events.actor`），**无身份/无校验/不落在案件上**，调用点仅
    立案与结案两处。之前演示里出现的「张警官」是**测试时手输的值**，代码与种子数据中无此角色
    （全库仅 UI 占位文字「如 XX派出所 王警官」）。故 `actor` ≠ 经办人。
  - **三个量级**（成本差很大）：
    | 层 | 内容 | 成本 |
    |---|---|---|
    | L1 审计标签 | 自由文本"谁点了按钮" | ✅ 已有 |
    | L2 经办人（= 分配 + 经办） | 案件有归属人、可分配/转派；能查"谁在办""哪几单没人办" | 中（见下） |
    | L3 组织/角色/权限 | 机构（派出所）、角色（接警/办案/协查）、权限边界、多租户隔离 | 大（= 半个业务系统，见 §四） |
  - **若做，推荐先只做 L2 子集**：`cases` 加 `handler` + `assigned_at`，加 `assign` 动作（含转派），
    记审计（复用 `actor`：谁把案子派给谁），`case.html` 展示 + 筛选。**不做**登录/密码。
    好处：立刻能回答"这单谁在办 / 哪几单没人办"，并把 §三告警那条的缺陷一并解决
    （A 方案的「已接手/处置中」就是 L2 的前半）。
  - ⚠ **动手前必须先定两件事**（否则会做歪）：
    1. **两类人不能同表**：`registry.persons` 是**走失者台账**（被寻找对象）；经办人是
       **系统中的人**（操作者）。加 L2 会出现第二类人，必须另存（如 `operators` 表），
       绝不能塞进 `persons`。
    2. **命名歧义**：现在的"立案"是 **ORPAH 侧登记**（把该人名下设备标走失态 + 下发 LOST-TABLE），
       **不是公安立案**。两者含义不同，混着叫会让人误以为本 demo 是公安办案系统。
  - **边界（重要）**：ORPAH 是**技术搜寻手段**，不是公安办案系统 —— 真实的"立案/分配/经办"
    属警方系统职责；ORPAH 侧真正需要的只是"这单谁在跟、找谁对接"。故 **L3 很可能超出本项目边界**，
    除非要把 demo 当"运营平台"演示。做 L2 前建议先确认这两类人是否真的存在（demo 里目前没有登录者）。
- [ ] **回放**：按时间段回放报文流 + 定位轨迹 + 安全事件。
- [ ] **重放/篡改自动化测试台**：批量用例（黄金样本、边界 SN、过期 nonce、错 CC）一键跑并出报告。

## 七、第三方素材与许可（2026-09-11 核实）

| 素材 | 位置 | 许可 | 义务 / 风险 |
|---|---|---|---|
| **Leaflet 1.9.4** | `ui/static/vendor/leaflet/`（已入库） | **BSD-2-Clause** | 保留版权与许可文本（已附 `LICENSE-leaflet.txt`）；可商用、无 copyleft |
| 底图瓦片 | 运行时外部请求，**不入库** | 各源不同 | 见 `track.html` 的 `TILE_PROVIDERS`；页面上选了哪个源就显示对应条款提示 |

**底图要点（选型时必读）**：

- `tile.openstreetmap.org`（默认）受独立的 [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 约束：
  必须**可见署名**、必须**可识别 UA**（网页场景浏览器默认 UA 可接受）、必须**遵守缓存头**（≥7 天）；
  **禁止**批量下载 / 预取 / 离线打包 / 高倍自动扫图；**无 SLA，可无预警封禁**。
- **OpenTopoMap** = CC-BY-SA 3.0：可商用、免许可费；需按官方文本署名
  （`Map data: © OpenStreetMap contributors, SRTM | Map style: © OpenTopoMap (CC-BY-SA)`，
  不能简写），且衍生作品需相同方式共享。
- **CARTO**：**已从「瓦片源」列表移除** —— 其栅格端点现在必须 API key，实测整图返回
  `API KEY REQUIRED — carto.com/basemaps/apikey` 水印；且其地名也是当地语言，解决不了英文界面的地名问题。
- **Esri**：商业服务商，生产使用前需单独确认条款（可能需账号/付费）；World Imagery 是卫星影像、**无地名**。
- **底图地名语言**：栅格瓦片是预渲染图片，地名是像素，**没有 `lang` 参数** ——
  中国境内用 OSM/OpenTopoMap 必然是中文。故「瓦片源」列表**按界面语言给不同的一套**：
  中文界面街道图优先（地名中文是优点），英文界面把无地名的 Esri 置默认、带地名的标出 ⚠ 提醒。
  真要英文地名只能走**矢量瓦片**（MapLibre GL + 样式指定 `name:en`）或自建栅格瓦片。
- **结论**：本库演示用法（网页内嵌 + attribution 控件 + 可自定义源）合规；
  但**产品化与离线场景不得依赖 OSM 官方瓦片**。
