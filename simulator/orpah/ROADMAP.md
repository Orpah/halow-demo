## 〇、范围原则（最高约束，2026-09-11 用户定）

> **ORPAH 是技术搜寻手段；demo 项目边界应取最小。**

- **只做「用无线技术找到人」这一段**：登记走失态 → 下发走失表 → 路由器发现上报 →
  服务器回执落库 → RSSI 定位 → 审计与告警。
  **ORPAH 不是公安办案系统**，不承载警务流程。
- **默认不做**（除非用户明确要求，且能论证它服务于「搜寻」而非「办案」）：
  组织/机构建模、角色与权限体系、警员身份、案件分配/派单/办案流程、多租户隔离。
- **判据**（每条新需求先过这一关）：
  **「让找人更快更准」→ 做；「让管理/流程更完整」→ 默认不做，先记本清单。**
- **「谁」的分层**：需要「谁」时止步于**审计标签**（自由文本 `actor`，见 §三）；
  需要「谁负责」（经办/分配）时先确认**是否存在真实运营方** —— demo 目前**无登录者**，
  自填标识不等于身份。
- **已应用**（2026-09-11）：「案件经办/分配」（见 §三）与「告警处置态/时效策略」（见 §三）
  均按此原则**只记录、不实现**。

## 一、设备与身份侧（最像「产品」的缺口）

- [~] **密钥/证书生命周期**（2026-09-12 主体完成）：密钥生成→分发→轮换→吊销→退役闭环；ES256 公钥、HMAC 密钥与 SN 绑定；作废机制（CRL/OCSP 思路）。
  - **已做**：`orpah_id.KeyStore` 多代密钥 + 状态机（`active`/`grace`/`retired`/`revoked`）；
    `keystore.KeyStoreDB` 落 SQLite（与清册同库，**重启不丢**）；`/api/keys` + `keys.html`
    （契约见 `API.md` §9）；每步写审计事件 `key_issue`/`key_rotate`/`key_retire`/
    `key_revoke`/`key_unrevoke`（带 `actor`，见 §三 审计）。
  - **轮换不断链**：旧钥进 grace（`ORPAH_KEY_GRACE_SEC`，默认 7 天）期内**新旧都能验签**，
    在役设备不必与服务器同时换钥；宽限到期 `sweep` → `retired`。
  - **不改报文格式**：报文头**不加 kid**，验签按代次倒序**逐代试签** → 老报文/老设备零改动；
    命中哪代回 `kid`/`gen`，并写进 `id_report` 事件的 `detail`（`gen=<n>`）；页面 / 事件历史可见
    「这条上报用的是第几代钥」。
  - **撤销不可逆**：整机作废后 `issue`/`rotate` 被拒（需先 `unrevoke` 再重新签发）；
    协议层 `_issue` 亦有同名护栏（双保险）。
  - **模拟器私钥不入库**：由 (SN, 代次) 确定派生（`derive_demo_privkey`）→ 服务器重启后
    公钥仍对得上（否则持久化的密钥库每次重启都验不过）；真实设备用 `demo_key=False`。
  - **未做（两个真缺口）**：
    1. **作废表分发（CRL/OCSP 思路）**：Router 侧目前**不知道**某 SN 已撤销，仍会转发其上报，
       由 Server 拒签（能兜住，但不是最小权限）。
       **📝 方向已定（2026-09-12 用户定），代码未写 —— 本项按 §〇 只记录不实现**：
       - 契约 = 新报文 `ORPAH-CRL`（S→R 推）/ `ORPAH-CRL-REQ`（R→S 拉）/ `ORPAH-REVOKED-SEEN`
         （R→S 安全事件），**与 `LOST-TABLE` 完全同构**（启动拉一次 + 变更推送 + 已同步不再按条拉，
         照抄 L3b 踩过的洪泛坑），但**语义分开**：走失表=业务数据、撤销表=安全数据（混表以后难拆）。
       - **Router 行为 = 命中即不转发 + 本地计数 + 上报安全事件**（选它而不是静默丢弃：
         「有人在用已撤销设备」本身就是安全线索，静默丢弃会丢失可见性）。
       - Server 仍是最终防线（Router 未同步时照样拒签）。与 §四 的「路由器侧观测不入签名」
         **是两回事**：这条管**身份还可不可信**，那条管**观测可不可信**。
       - 落点：`orpah_proto.py` + `server.py` + `router.py` + 端到端脚本 `demo_l5.py`；
         协议侧已写进 `Protocol/docs/orpah-over-halow/SPEC.md` §5.1 / F-10 / L3d。
    2. **密钥存储保护/产线烧录**：安全元件、私钥不可导出、供应链绑定 —— 属**硬件信任根**，
       按 §〇 范围原则**不在本 demo 范围**（只记录）。补充事实：demo **服务器侧本来就不存设备私钥**
       （模拟器私钥按 (SN, 代次) 派生，真机私钥在设备内），所以「服务器加密落库」对 demo 无实际收益；
       真正要保护的是**真机设备侧私钥**（安全元件 + 不可导出 + 产线注入），留待真机阶段。
- [ ] **多算法策略与降级**：按设备安全等级自动选 alg；私钥不可用/能量不足自动降级并告警。
- [ ] **无源/低功耗客户端建模（协议约束，非仅画像）**：无源唤醒周期、能量采集状态、上报间隔——能量决定上报频率与 alg 降级；demo 加「能量轴」。

- [~] **定位质量量化**：GDOP/PDOP、加权最小二乘（权重随距离增大而减小，σ∝距离）、误差椭圆/置信半径、滑动平均 + 卡尔曼滤波。
  - 已做（2026-09-11）：**残差 RMS**（每个站位「测量 − 估计」逐条列出 + 总体 RMS 分级）、
    **GDOP**（估计点到各站位单位向量，越小越好）、**站位布局条件数**（λmax/λmin，∞ = 完全共线）
    用于「解不出来」时区分是站位几何不行还是距离环不相交。
    为何必做：恒定 RSSI 这类退化输入会让 LS 解落在「外接圆心」，看着像个正常坐标、实际无意义。
    实测：给一组由真值点反算的 RSSI → 精确解回 `(0.0, 0.0)`、RMS 0.0、GDOP 1.22。
  - **已做（2026-09-12，加权 LS + 误差椭圆/置信半径）**：
    - **加权最小二乘**：权重 `w = 1/σ²`、`σ = max(1 m, 0.25×距离)`（RSSI 测距误差随距离增长）。
      为何必需：远端站位距离本就不可信，等权 LS 会被它拽偏 —— 实测一组「远端 +40 m 误差」：
      等权解偏离真值 **65.5 m**，加权解 **0.069 m**（远端权重被压到 1/576）。
    - **高斯-牛顿 + 步长折半线搜索**：测量不自洽（距离环不相交）时裸 GN 会振荡打满迭代，
      线搜索保证代价单调下降，并在「无步长可降」时判收敛；不收敛会**明确报出来**，不偷偷给个点。
    - **95% 置信椭圆 + 搜索半径**：协方差 `(JᵀWJ)⁻¹`（先验噪声模型）× `max(1, σ̂0²)`（后验更差才放大），
      特征值 → 半轴、特征向量 → 方位（χ²(2,0.95)=5.991）；搜索半径 = 沿最长轴的 95% 覆盖半径。
      **为何不用 σ̂0²(JᵀWJ)⁻¹**：恒定 RSSI 这类「自洽但错误」的输入残差≈0 → σ̂0→0 →
      会给出「零不确定度」的假自信（本页一直在防的那类坑）。
    - 页面：真实模式新增「加权解 / 95% 置信 / 搜索半径」三行 + 每站位距离带 ±σ；
      画布与地图都画椭圆（黄虚线）；`track.html` 模拟模式仍用原线性解（本项只动真实模式）。
    - 验收：由真值点反算 RSSI → 绑定 → WLS 复原到 **(5.0, 5.0)**（真值 5,5）、残差 0.1 m、
      椭圆 19.8×12.3 m、方向 67°；精确距离输入复原误差 2.7e-15；共线站位→加权法方程奇异（回退线性解+提示）。
  - **已做（2026-09-12，时序平滑 = 恒速卡尔曼）**：
    - **为什么是卡尔曼、不是滑动平均**（先回答了「与搜索半径的关系」才动手）：移动目标上 N 点平均
      的滞后 ≈ (N/2)×采样周期；找人场景里「滞后」就是「指错位置」。合成场景（半径 12 m 圆、
      1.2 m/s、2 s 采样、RSSI ±2 dBm）实测：原始 RMS 4.5 m → **卡尔曼 3.5 m / 5 点平均 3.4 m**
      （降噪量接近），但**滞后 卡尔曼 0.4 m vs 5 点平均 2.7 m**。且只有卡尔曼能给出**滤波后协方差**。
    - **搜索半径用滤波后协方差 P（含过程噪声 Q + 测量噪声 R），不用测量协方差**：
      否则会把「输出更平滑」误当成「更准」，给出**过小**的搜索半径（假自信 —— 本页反复防的坑）。
      实测平滑后半径 27.3 m → 21.9 m（σ 7.5 m → 6.3 m），**95% 椭圆对真值的覆盖率 100%**（合成场景，
      100 帧）→ 半径可信、没有过度自信。
    - **实现**：`pos.js` 新增 `kalmanTrack(frames)`（4 状态 CV：x,y,vx,vy；松耦合位置量测；
      长时间缺口 reset；输出 `{t,x,y,vx,vy,cov,reset}`）+ `pathJitter()`。
      **协方差更新用 Joseph 形式** `P=(I−KH)Pp(I−KH)ᵀ+KRKᵀ`：更短的 `P=(I−KH)Pp` 在浮点下会丢掉
      对称正定，跑几十帧后创新协方差近奇异 → 增益暴冲 → 状态发散（**实测**：真实数据第 84 帧
      从 −11 m 跳到 12000 m，改用 Joseph 后全窗 793 帧全部有限）。
    - **工程决策：坚持算法单一源** —— A/n、观测取值（bind > 窗口中位数 > 路由器序列）、WLS、滤波
      全在 `pos.js`，`track.html` 与 `replay.html` 共用；页面只画两条线（红=原始、绿=平滑），不另写算法。
    - **为让平滑可验证，先补了测量噪声**（`motion.py` 的 `NOISE_DB=2.0`，SHA-256 确定性噪声、逐站位不同）：
      无噪声数据的定位结果本来就是真值，平滑/椭圆/残差都失去意义（RMS 恒 0.12 m）。
    - **诚实的边界**：真实演示数据噪声小（±2 dBm），而 WLS 的噪声模型 `σ=max(1, 0.25×距离)` 偏保守
      （比实际大 ~2.4 倍）→ 滤波更信测量 → **真实数据上平滑幅度有限**（抖动 3.5→3.1 m，−12%）。
      若真机 RSSI 误差标定得更准，可收紧该模型让滤波发挥更大作用（属阶段二标定工作）。
  - **未做**：无（时序平滑完成）。

    只要案件还是 `open` 就永远红着（`since` = 立案时间，级别不随时长变化），于是：
    1. **红点恒亮 → 被淹没**：红点变成常态背景，不再表示"有变化需要看"，
       连刚做的「新告警闪一下」也失去意义（底色永远是红的，看不出新旧的差别）；
    2. **级别无增量**：`持续 5 分钟` 与 `持续 10 小时` 同为 `crit`，
       分不出"刚超时、还没人管"和"已经在找人"。

    而在**缺少处置态**（下面 A 的依据）。
    候选方向（择一或叠加）：
    - **A. 加处置态（推荐）**：案件加「已接手/处置中」+ 接手人（记审计，复用 `actor`）。
      规则改为「超时 **且** 无人接手」才算告警；点「已接手」→ 红点消失、案件转入处置中跟踪
      （时长继续累计、案件页可见）。代价：`cases` 加状态字段 + `case.html` 按钮 + 过滤。
    - **B. 加时长上限**：超上限（如 `ORPAH_ALERT_CASE_MAX_SEC`，默认 24h）自动退出告警，
      理由是长期未结属"案件积压"，应在案件台账看。改动最小，但"长期没人管"在红点上不可见。
    - **C. 分级升级**：按持续时长换级别/文案。信息更细，但红点仍恒亮，"淹没"未解决。
    - 也可 A + B：A 为主，B 兜底（认领后仍超 24h 再提醒）。

## 五、可观测与交付物

- [ ] **回放视频联动（摄像头画面）**（2026-09-12 用户提，**只记录、不做**；见下面细节）：
  回放页右侧显示**最多 4 路**摄像头画面，画面时刻**随回放进度联动**（人走到哪里，那一秒的画面就出哪里）；
  并把摄像头的**位置与视角（视锥）**在地图/画布上画出来。
  - **待定设计问题（动手前先定）**：
    1. **视频源形式**：演示优先用**本地文件**（mp4/webm，可 seek、可变速）；真实系统是 RTSP/HLS ——
       浏览器**不能直接播 RTSP**，必须服务端转封装（HLS/fMP4/WebRTC），属另一条工程线。
    2. **时刻对齐（核心）**：每路摄像头需要**录像起点 epoch**（+ 时区/偏移）→
       `videoTime = 回放光标时刻 − 录像起点`；seek 时 `video.currentTime = videoTime`，
       倍速用 `video.playbackRate = 回放倍速`，暂停就全暂停。没有起点时间戳就谈不上联动。
    3. **摄像头元数据存哪**：新增 SQLite 表（与 `stations` 同级）：`sid/name/x/y/朝向角/FOV/可视距离/录像起点/源地址`。
       按「摄像头 = 另一类传感器」建模，不要塞进 `stations`（站位是测 RSSI 的点，语义不同）。
    4. **视角绘制**：位置点 + 视锥扇形（朝向 ± FOV/2、可视距离）——画布用 `ctx.arc`，地图用 `L.polygon`；
       与现有站位/椭圆同属一层。
    5. **性能**：4 路同时解码很吃 CPU/内存 → 只播「当前时刻在录像区间内」的几路、`preload="none"`、
       切时段时先 `pause()` 再换 `src`；画布/地图上的摄像头标记与回放同一签名更新。
    6. **隐私与边界**：视频是最敏感的一类数据（人脸 + 位置）——
       demo 里**只用自制/无隐私的示例视频**；真实部署涉及人脸识别、留存时长、调阅授权，
       均**超出本 demo 边界**（与 §〇 范围原则一致：这属于「提升态势感知」，不是「让找人更快更准」的必要条件）。
  - 依赖：先有「移动的人」的样例数据（人不动、只有 4 路画面联动是看不出效果的）。

- [ ] **指标面板**：校验失败率、签名算法分布、平均 RSSI、定位误差 CDF、走失处置时长。
- [ ] **配置中心**：路径损耗 A/n 校准值、各 router 坐标、锚点库、基图参数、SSE/API 地址外置。
- [ ] **文档/导览**：协议版本↔页面功能映射、黄金样本一键自检、demo 剧本（入网→移动→走失→撤销→定位→找回）。

| 素材 | 位置 | 许可 | 义务 / 风险 |

| 底图瓦片 | 运行时外部请求，**不入库** | 各源不同 | 见 `track.html` 的 `TILE_PROVIDERS`；页面上选了哪个源就显示对应条款提示 |
| **离线网格底图** | `ui/static/map.js`（代码即素材，跟着代码入库） | **无第三方素材** | canvas 现画的网格/背景色，**不含任何第三方数据** → 不引入许可义务（这正是选它而不是随包分发瓦片的原因） |
| （将来）PMTiles 区域包 | 运行时本地文件，**不入库** | Protomaps basemap（数据源 OSM = ODbL） | 需自托管 + 署名；**不得**用 OSM 官方瓦片打包；做法与 Range 前置条件见 §二 |

**底图要点（选型时必读）**：

- `tile.openstreetmap.org`（默认）受独立的 [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 约束：
  必须**可见署名**、必须**可识别 UA**（网页场景浏览器默认 UA 可接受）、必须**遵守缓存头**（≥7 天）；
  **禁止**批量下载 / 预取 / 离线打包 / 高倍自动扫图；**无 SLA，可无预警封禁**。
- **OpenTopoMap** = CC-BY-SA 3.0：可商用、免许可费；需按官方文本署名
  （`Map data: © OpenStreetMap contributors, SRTM | Map style: © OpenTopoMap (CC-BY-SA)`，
  不能简写），且衍生作品需相同方式共享。
- **CARTO**：**已从「瓦片源」列表移除** —— 其栅格端点现在必须 API key，实测整图返回
  `API KEY REQUIRED — carto.com/basemaps/apikey` 水印；且其地名也是当地语言，解决不了英文界面的地名问题。
- **Esri**：商业服务商，生产使用前需单独确认条款（可能需账号/付费）；World Imagery 是卫星影像、**无地名**。
- **底图地名语言**：栅格瓦片是预渲染图片，地名是像素，**没有 `lang` 参数** ——
  中国境内用 OSM/OpenTopoMap 必然是中文。故「瓦片源」列表**按界面语言给不同的一套**：
  中文界面街道图优先（地名中文是优点），英文界面把无地名的 Esri 置默认、带地名的标出 ⚠ 提醒。
- **离线场景（2026-09-12）**：本 demo **不含离线底图**（OSM 政策禁止；自建 PMTiles 需要额外数据包，
  用户定为「不下包」）。瓦片取不到时自动回落**本地自绘网格**（无第三方素材 → 无许可义务），
  并在图上明确提示「离线：底图取不到」+「重试底图」。
  真要英文地名只能走**矢量瓦片**（MapLibre GL + 样式指定 `name:en`）或自建栅格瓦片。
- **结论**：本库演示用法（网页内嵌 + attribution 控件 + 可自定义源）合规；
  但**产品化与离线场景不得依赖 OSM 官方瓦片**。
