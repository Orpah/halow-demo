# simulator/hardware/wiring/ —— 台面接线图

本目录放**台面夹具的接线图**（Fritzing 工程 + SVG 导出）。**一张图只描述一种接线**，
图的权威内容 = `.fzz` 的网表（不是图上的画法）。

| 文件 | 说明 |
|---|---|
| `pcpeer-ch347f-nanoch32v203.fzz` / `.svg` | **PC 当空口对端（单板）**：nanoCH32V203（跑本仓 `firmware/`）+ CH347F。`P2`（UART0 = **COM23**）当**控制台**、`P3`（UART1 = **COM24**）当**虚拟空口**；空口对端不是第二块板，而是 PC 上的 `python host/sim.py --link-serial COM24`。 |

## 接线正确性怎么复验（不靠肉眼数线）

```powershell
python simulator\tools\fzz_nets.py            # 退出码 0 = 全部对上；1 = 有差异（信息里说差在哪一格）
```

脚本按 Fritzing 自己的存储方式把 `.fzz` 解成网表 —— ① 每个 instance 的
`<connector>/<connects>`；② **每条 wire 自身导通两端**；③ 部件 `.fzp` 里的**内部 `<bus>`**
（例如 CH347F 的多个 GND、nano 的多个 VSS）—— 并成网后用 union-find 归并，
再与脚本里的 `EXPECT`（= **规格的单一源**，改图先改它）逐网比对；跨实例却不在规格里的线会被当
「多出来的连线」报出来。

## 规格：`pcpeer-ch347f-nanoch32v203`（共 5 根线：4 信号 + 1 地）

| nanoCH32V203（丝印 / 芯片脚） | CH347F-EVT | 用途 |
|---|---|---|
| `A9`（PA9, USART1_TX） | `RXD0`（`P2`） | 控制台（CH347F TX 侧不用管，见下） |
| `A10`（PA10, USART1_RX） | `TXD0`（`P2`） | 控制台 |
| `A2`（PA2, USART2_TX） | `RXD1`（`P3`） | **虚拟空口**：板 → PC 模拟器 |
| `A3`（PA3, USART2_RX） | `TXD1`（`P3`） | **虚拟空口**：PC 模拟器 → 板 |
| `G` | `GND` | 共地（唯一的地） |

- **方向口径（别接反）**：`TXD0 → PA10`、`PA9 → RXD0`；`TXD1 → PA3`、`PA2 → RXD1`。
  （波特率 115200 8N1，两路都是。）
- ★ **前提：模组（TX-AH EVB）整块不接**。它原先占着 nano 的 `A2/A3`（数据口）与 CH347F 的
  `P3`（它的 AT/打印口）—— 不拔掉就会把两个 TX 并到一根线上。
- **电源不连**：nano 走自己的 USB 供电；**CH347F 的 `3V3`/`VIO` 不接**（避免两个 3.3V 源并联），
  只共地。
- ✔ **2026-09-21 实物已按本图接好、配对成功**（板子当 AP，PC 侧 `host/sim.py --link-serial COM24` 当 STA）。
  ★ 踩过一次：`PA2/PA3` 与 `TXD1/RXD1` **接反（TX↔TX）**时，症状是
  **「板上 `link_tx` 在涨、PC 侧恒空闲/离线 + 板上 `link_rx=0`」** —— 遇到这个组合
  **先查这两根是否交叉**，别去调 SSID/信道/带宽。
- ⚠ **仍未验证**：SPI 宿主口、板上 LED/按键/拨码（本夹具的板是 nano，没这些器件）。
  **别把"图核对通过"当成"联调通过"。**
